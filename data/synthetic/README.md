# Targeted robustness set

**64 rows** built from the gaps in the coverage matrix
(`../../docs/09-coverage-and-blind-set.md`), not at random. One row per gap between what the
client's catalogs contain and what the 15-row MTO exercises.

| File | What |
|---|---|
| `MTO_sintetico.xlsx` | The 64 rows in the same 6-column format as the real MTO, including the `MATERIAL` column trap |
| `expectativas.csv` | Gap covered and expected behavior per row |
| `MTO_sugerencias.xlsx` | Test bed for **several** vocabularies, not just finishes. Generated by `pnpm run mto:synthetic`. `MTO` sheet with extra columns (`NOMBRE`, `NORMA`, `ACABADO`) so each token lives in its own cell; `guia` sheet (not read by the pipeline) says what to impute in each row. Not gold |

## Two rules

1. **Generated from `reglas_tornilleria.md`, not from the given MTO.** It covers what the blind set
   is going to explore, not what is already known to work.
2. **Not run until day 4.** If used to iterate from day 2 onward, it stops measuring
   generalization and becomes a second training set. It is the blind set's own property.

The expectations were written **before the system existed**. It is the only way for them not to
be biased by what the system ends up doing.

## `MTO_sugerencias.xlsx` — imputing vocabulary

The real MTO mixes name, standard, quality, and finish in `DESCRIPCION`. This file **splits each
token into its own column** so multiple vocabularies' onboarding can be exercised without guessing
the cell.

`MTO` sheet (the one the pipeline processes):

```
ITEM | DESCRIPCION | MATERIAL | MEDIDA | CANT. | UD | NOMBRE | NORMA | ACABADO
```

`MATERIAL` remains the real MTO's trap: it is almost never the material, it's the quality. Ingest
concatenates all text cells, so `NOMBRE` / `NORMA` / `ACABADO` enter `sourceText` just like
`DESCRIPCION`. The token is **not duplicated** in the description.

`guia` sheet: item → vocabulary → token → whether it's editable today. The pipeline ignores it
(it only reads the first sheet with headers).

| Block | Column | Editable today | What's expected |
|---|---|---|---|
| finish | `ACABADO` | yes | P-12 → Under review; onboarding at `/vocabulario?attr=finish` |
| finish (control) | `ACABADO` | — | alias already in the table (`HDG`, `GALVA`, `YZP`, `zingue`, `black`, `phosphate`, `zincadas`) → resolved by table, green queue |
| finish (guard) | `ACABADO` (`A2`, `galv`) | — | `A2` is quality, not finish: the guard between attributes doesn't exist yet; `galv` alone is ambiguous and onboarding decides it |
| material | `MATERIAL` | yes | ASTM quality without derivation → material onboarding |
| material (control) | `MATERIAL` | — | `GR B16`, `A4-80`, `GRADE 5`, `A2-80` already have an entry → resolved by table; `A2-80` watches that G2 doesn't turn into A2 |
| material (deliberately not derived) | `MATERIAL` (`200HV`) | — | `deliberatelyUncovered`: neither derives nor suggests; if it suggests, something is broken |
| quality | `MATERIAL` (`GR 12H`) | no | outside §5; 45H is already decided and doesn't serve as a test bed |
| name | `NOMBRE` | no | `vis` already in §3; `bullone`/`parafuso` out of family; `Schraube` + `verzinkt` double candidate |
| standard | `NORMA` | no | unknown family or ASME/UNI/BS without DIN→ISO equivalence |
| mix | `ACABADO` + `MATERIAL` | yes (both) | two onboardings on the same row; and the crossed case: finish already in table + material pending |
| control | — | — | already covered, green queue |

```bash
pnpm run mto:synthetic          # regenerates the xlsx
```
